1. SUMMARY
--------------------------------------------------------------------------------
M’AND connects an Android phone and a Mac over your own Wi-Fi. There is no
cloud, no account and no subscription, and every connection is encrypted.

Status in one line:
  All planned features are built. The Mac app is built, tested and running on
  this Mac. The Android app is built (MAND-0.2.0.apk) but has NOT yet been run
  on a real phone. That real-phone test is the one remaining step.

Cost so far: ₹0. Only free and open-source tools were used.


2. WHAT M’AND DOES
--------------------------------------------------------------------------------
Feature                          Mac app            Android app
-------------------------------  -----------------  ---------------------------
Secure pairing (QR + "Allow")    Built, tested      Built, not yet on a phone
Connection status, auto-         Built, tested      Built, not yet on a phone
reconnect, forget device
Send files both ways             Built, tested      Built, not yet on a phone
(resume, no overwrites)
Clipboard text sharing           Built              Built, not yet on a phone
Phone notifications on the Mac   Built              Built, not yet on a phone
Phone battery level on the Mac   Built              Built, not yet on a phone
Screen mirroring (scrcpy, USB)   Built              Needs USB debugging only
Start at login / reconnect       Built              Built, not yet on a phone
after phone restart

How each feature works for you:
  • Pairing:
      - On the Mac, click "Pair a Phone".
      - On the phone, scan the QR code.
      - Back on the Mac, click "Allow".
    Nothing is trusted until you click Allow.
  • Files:
      - Mac to phone: drag files onto the Mac app's Files screen.
      - Phone to Mac: in any phone app, use Share → "Send to Mac".
      - Where files go: on the Mac, Downloads/M’AND (you can change this in
        Settings); on the phone, Downloads/M’AND.
      - If the connection drops, the transfer continues where it stopped.
      - Every file is checked for damage.
      - Existing files are never overwritten: a second file with the same name
        becomes "name (2)".
  • Clipboard:
      - Off by default on both sides.
      - Passwords and items marked private are never sent.
      - On the phone, sending always needs a tap (an Android rule): use the
        button, the Quick Settings tile, or the Share sheet.
  • Notifications:
      - Off by default. You choose which phone apps are shared.
      - Dismissing a notification on the Mac also dismisses it on the phone.
  • Battery: the real level and charging state are shown on the Mac.
  • Screen mirroring:
      - Uses the free tool "scrcpy", which you install once, and a USB cable.
      - View-only unless you switch on "allow control".

What is NOT possible (platform limits, not missing work):
  • Talking or listening to phone calls on the Mac. macOS can't act as a
    phone's hands-free device, and Android doesn't give apps call audio.
  • Reading the phone's clipboard automatically in the background. Android
    blocks it.
  • Full SMS and RCS access. Restricted by Android; new messages still appear
    on the Mac as notifications.
  • Seeing one-time codes in notifications. Android 15+ hides them from apps
    like M’AND for safety.


3. HOW IT IS BUILT (simple version)
--------------------------------------------------------------------------------
  • Mac app:     Swift + SwiftUI (Apple's own tools). Code name: MandMac.
  • Android app: Kotlin + Jetpack Compose (Google's own tools). Code name:
                 MandAndroid.
  • Shared rulebook: one protocol document (protocol/PROTOCOL.md) plus a file
                 of shared test cases. Both apps must pass the same cases, so
                 they always agree.
  • Connection:
      - The Mac waits for connections and the phone connects to it, over
        local Wi-Fi.
      - Security is TLS 1.3, the same encryption banks use.
      - Each device has its own secret key, which never leaves its secure
        storage (Mac Keychain / Android Keystore).
      - Each side only accepts the exact device it paired with.
  • Size: about 9,000 lines of code (about 4,200 Swift and 3,400 Kotlin app
    code, the rest tests), in 14 saved versions (git commits).


4. SECURITY
--------------------------------------------------------------------------------
Protections in place:
  • Encryption and identity:
      - Every connection is encrypted (TLS 1.3, both devices prove who they
        are).
      - Pairing needs the QR code (5 minutes, single use) AND your click on
        "Allow".
      - A forgotten device is cut off immediately and can't come back without
        pairing again.
  • Files:
      - File names from the other device are cleaned, so a file can never be
        written outside the download folder.
  • Abuse limits:
      - Too many connections, oversized messages and malformed data are
        rejected.
  • Privacy:
      - Nothing is sent to the internet.
      - The activity log never records message contents.
      - Sharing features (clipboard, notifications) start switched OFF.

Independent AI reviews (3 reviews) and what they found:
  1. Connection review: no critical issues.
     One serious bug: pairing failed if you took more than about one second to
     click Allow. FIXED, and a test now checks it.
  2. Android code check: several crash and logic bugs. ALL FIXED.
  3. Features review: ONE CRITICAL issue.
     - The problem: on the Mac, a specially crafted file name from a paired
       phone could have saved a file outside the download folder.
     - The fix: done, and tests now try that attack and a symlink variant on
       every run.
     - Also: about 15 medium/low issues fixed the same day.

Remaining known risks (see docs/SECURITY.md):
  • Testing:
      - The Android app hasn't been tested on a real phone yet.
      - No professional (human) security audit has been done.
  • Trust and limits:
      - A paired phone is trusted, so only pair phones you own.
      - Only one phone can be connected at a time.
  • Signing:
      - The Mac app uses a free local signature: fine for personal use, but
        not for giving to other people.
      - The Android app uses a development signature: fine for personal
        installs.

6. PROBLEMS MET DURING THE BUILD (and how they were solved)
--------------------------------------------------------------------------------
  • No Xcode on the Mac:
      - The Mac app was built with Apple's free Command Line Tools instead.
      - Two Apple tool quirks needed workarounds: a missing compiler plugin
        for "@State", and a test plugin that loaded unreliably. Both solved,
        and tests now pass every time.
  • The apostrophe in the folder name "M’AND" broke the Android test tool:
      - Android build output now goes to ~/.mand-build instead.
  • The Mac app froze at launch:
      - It was waiting on a macOS "access Downloads?" prompt. Fixed, so no
        protected folder is touched at startup.
  • Early test runs left 9 test keys in your login keychain:
      - Removed, and the tests now use a throwaway keychain.
  • A downloaded build-tool file didn't match its official fingerprint:
      - It was rejected and a verified one generated instead.
